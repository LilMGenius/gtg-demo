# 시장 검증 실행 묶음

상태: DRAFT. 공개 게시, 모집, 결제, 수집기 계정 생성과 연결은 승인 전이다. 이 묶음은 준비 여부를 재며 시장 통과나 출시를 선언하지 않는다. 제품 범위는 페널티킥 반복, 훈련과 성장이다.

## 무엇을 재는가

플레이 여정 순서로 읽는다. 계산과 결측 처리는 [결과 보고 틀](report.md)이 소유한다.

| 지표 | 질문 | 관측 방법 |
| --- | --- | --- |
| 첫 세트 완주자 중 두 번째 세트 진입 비율 | 첫 반복 뒤에도 남는가 | 같은 설치의 첫 세션에서 set_complete 뒤 second_set_start, 관찰지의 자발적 지속 여부 병기 |
| D1 재방문 | 다음 날에도 다시 여는가 | 첫 first_playable 설치 코호트와 다음 현지 달력일의 실제 플레이를 연결 |
| 세션 길이 | 반복이 시간을 붙잡는가 | 관찰자가 실제 시작·종료와 숨김 시간을 기록; 이벤트 간격은 하한만 계산 |
| 손과 봇 비중 | 사람이 남았는가, 자동 진행만 남았는가 | set_complete.mode별 완주 수와 관찰한 활성 시간을 별도 보고 |

두 번째 세트는 자동으로 이어진다. 진입 이벤트만으로 다시 하겠다는 의사를 판정하지 않는다. hand도 봇이 아니란 뜻이지 실제 입력의 증거는 아니다. 손을 뗀 채 열린 탭과 자발적 지속을 관찰지에서 구분한다. first_contact는 세션 최초 접촉이지 세이브 성공이 아니다. return_visit는 저장이 있는 재로드에서도 나므로 그 수 자체를 D1으로 쓰지 않는다.

## 판정선

<!-- 절반, 웹 D1 범위와 세션 시간은 기록 PLAN의 P24·12절 및 정본 EVIDENCE L5가 지정한 수치이며 완화하지 않는다. -->
기록 정본은 [PLAN](https://github.com/DaedalGames/daedal-games/blob/feat/gtg/docs/gtg/PLAN.md)의 P24와 12절, 기준의 출처는 정본 docs/gamedev/EVIDENCE.md L5가 가리키는 [CrazyGames Basic Launch](https://docs.crazygames.com/resources/basic-launch-metrics/)다. 두 번째 세트 진입이 첫 세트 완주자의 50% 미만이면 채널 확대를 멈추고 게임을 고친다. 50% 이상이어도 외부 다섯 명의 관찰만으로 PMF나 출시 통과를 선언하지 않는다. 웹 D1 10% 미만은 조사, 10~15%는 계속 시험, 15% 초과는 좋은 신호다. 평균 세션 10분 이상을 함께 본다. 그 미만이면 반복·템포를 조사하고 리텐션만으로 확대하지 않는다. 모집단과 수집 신뢰도가 갖춰지지 않으면 미측정이다.

## 실행 순서

아래 순서대로 진행한다. 준비 주체는 루프, HITL 주체는 파운더다.

| 단계 | 담당 | 수행 |
| --- | --- | --- |
| 준비 확인 | 루프 | 원인·성장 게이트와 readiness 결과를 현재 빌드에서 재확인. 다른 작업의 과거 초록을 재사용하지 않음 |
| 수집기 승인 | HITL | 아래 결정표의 수집기 행 승인과 계정 생성 |
| 연결 확인 | 루프, 승인 후 | [수집기 절차](collectors.md)대로 시험 수신·내보내기·삭제를 확인하고 별도 승인된 연결 작업으로 endpoint 배포. 이 패키지는 빈 endpoint를 유지 |
| 외부 관찰 | HITL 모집 → 관찰자 | [관찰 대본](observer.md)과 [기록지](observation.csv)로 진행. 코칭·재방문 알림 없음 |
| 제한 코호트 | HITL 게시 | [게시 초안](posts.md) 중 승인한 채널의 글과 [클립 계획](clip.md)을 사용 |
| 집계 | 루프 | 원자료를 비공개 보관하고 [보고 틀](report.md)에 분모·결측·손/봇·빌드를 채움 |
| 전환 | HITL | 외부 관찰과 성숙한 D1을 읽고 다음 시험 또는 게임 수정 승인 |

## 한 번에 검토할 HITL 결정

실행 의존 순서이며 각 행은 결정 하나다. 권장안을 묶어 “예”로 승인할 수 있다. 실제 계정 생성·모집·게시·지출 집행은 파운더 손에 남는다.

| HITL 단계 | 필요한 결정 하나 | 제안 |
| --- | --- | --- |
| 수집기 계정 | Pipedream Free 계정과 시험용 수집을 허용하는가 | 허용 후 파운더가 계정을 만들고 endpoint를 비공개 전달 |
| 모집 | 코칭 없는 외부인 다섯 명을 모집하는가 | 지인 개발팀·내부 QA를 제외하고 동일 대본 사용 |
| 지출 | 무지출로 시험하는가 | 광고·사례비·유료 업그레이드 없이 진행; 한도 소진 시 중단 |
| 게시 | 준비된 문구와 클립으로 제한 모집을 시작하는가 | 먼저 Discord의 허용된 피드백 공간, 나머지는 승인된 공간에만 게시; 포털은 제출 초안 |
| 결과 전환 | 보고서의 판정에 따라 계속할 것인가 | 보고가 채워진 뒤 파운더가 결정; 사전 승인으로 대체하지 않음 |

영상 파일은 로컬 증거 폴더 '.omo/evidence/p24b/gameplay.mp4'다. 공유 작업트리에서 캡처한 DRAFT이고 게시 전에 배포 빌드와 일치 여부를 확인한다. 관찰 원자료·참여자 연락처·수신 URL은 추적 파일에 넣지 않는다. 채널 링크는 공개 게임 경로에 src만 붙이며 개인정보를 넣지 않는다.

준비 검증: 'node tools/readiness-gate.mjs'. 이 게이트의 package 행은 자료의 존재와 계약만 재며 외부인의 재미, 실계정 수신, 모집 성공은 재지 않는다.
